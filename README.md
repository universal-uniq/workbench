# Верстак

Статический каталог полезных программ для Windows, Linux и macOS. Работает на GitHub Pages: без сборки, без фреймворков, без аналитики.

Сайт читает два текстовых файла и строит карточки на странице: `source.txt` (программы) и `source-prompts.txt` (промпты). Ссылки ведут на официальные сайты и репозитории проектов.

## Состав

```
index.html                  разметка страницы
assets/style.css            оформление, темы, Liquid Glass
assets/app.js               разбор данных, поиск, фильтры, настройки
assets/theme-init.js        тема и акцент до первой отрисовки
assets/favicon.svg          иконка сайта
source.txt                  359 программ в 13 категориях
source-prompts.txt          15 промптов в 6 категориях
.github/workflows/pages.yml деплой на GitHub Pages
.github/dependabot.yml      обновление версий GitHub Actions
.nojekyll                   отключает обработку Jekyll
```

## Публикация на GitHub Pages

Содержимое папки `verstak` нужно сделать корнем репозитория (положить `index.html`, `assets`, `.nojekyll` и `.txt`-файлы в корень).

**Способ 1 — Actions (рекомендуемый):**

1. Создайте репозиторий, загрузите туда содержимое папки в ветку `main`.
2. В настройках репозитория откройте **Pages → Build and deployment → Source → GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` сработает при первом push в `main`. Сайт появится по адресу `https://<логин>.github.io/<репозиторий>/`.

**Способ 2 — без Actions:**

В настройках **Pages → Source → Deploy from a branch**, выбрать ветку `main` и папку `/ (root)`, нажать Save.

`.nojekyll` уже лежит в корне — он нужен, чтобы GitHub не обрабатывал файлы через Jekyll и отдавал `.txt` как есть.

## Настройки на сайте

В правой части шапки три элемента управления:

- **Палитра** — четыре готовых акцентных цвета и выбор любого цвета через системный пикер. Цвет сохраняется в браузере.
- **Жидкие карточки** — включает и выключает Liquid Glass (полупрозрачные карточки с размытием). По умолчанию выключено.
- **Тема** — светлая или тёмная. По умолчанию тёмная.

Выбор сохраняется в `localStorage` и не требует правки файлов.

## Формат source.txt

Категория задаётся строкой в квадратных скобках. Порядок категорий и строк на сайте совпадает с порядком в файле.

```
[Система]
Rufus | https://github.com/pbatard/rufus | https://example.com/rufus.png | win | open | Записывает загрузочные USB.
```

Поля через `|`:

| Поле | Обязательное | Значения |
|---|---|---|
| Название | да | любой текст |
| Ссылка | да | официальный сайт или репозиторий |
| Логотип | нет | прямой URL картинки (PNG, SVG, ICO) |
| Платформы | да | `win`, `mac`, `linux`, `web`, `android`, `ios`, `server`, `any` — через запятую |
| Лицензия | да | `open`, `free`, `freemium`, `paid`, `guide` |
| Описание | нет | одна-две строки, без воды |

Строки, начинающиеся с `#`, игнорируются. В описании можно использовать `|` — всё после пятого разделителя считается описанием. Файл сохраняйте в UTF-8.

Если логотип не указан, сайт пробует аватар владельца GitHub-репозитория или favicon сайта. Если картинка не загрузилась, рисует первые буквы названия на цветной плашке. Значение `-` в поле логотипа сразу включает буквенную плашку.

## Формат source-prompts.txt

```
[Код]
Ревью кода | Строгое ревью кода | code, review | Ты — строгий code reviewer, проверь код на ошибки и стиль.
```

Поля: название, описание, теги через запятую, текст промпта. Всё после четвёртого `|` считается текстом промпта. Категории — строка в квадратных скобках, комментарии начинаются с `#`.

## Локальный просмотр

`fetch()` не работает при открытии страницы через `file://`, поэтому нужен локальный сервер из папки сайта:

```bash
python -m http.server 8000
```

Затем откройте <http://localhost:8000>. Подойдут и `npx serve`, и Live Server.

## Безопасность

- Данные из `source.txt` и `source-prompts.txt` экранируются при выводе. Ссылки и логотипы принимаются только с `http(s)`; `javascript:` и `data:` отбрасываются.
- Внешние ссылки открываются с `rel="noopener noreferrer"`, логотипы запрашиваются с `referrerpolicy="no-referrer"`.
- CSP в `index.html` разрешает только локальные скрипты и стили, картинки по `https:` и запросы к своему домену. GitHub Pages не позволяет задавать HTTP-заголовки, поэтому политика задана через `<meta>`.
- Акцентный цвет из `localStorage` проверяется как hex-значение, тема — только `light` или `dark`.
- В workflow только необходимые права: `contents: read`, `pages: write`, `id-token: write`. Сторонних скриптов, счётчиков и аналитики нет.
- Логотипы грузятся с внешних CDN, поэтому эти CDN видят IP посетителя. Если это нежелательно, положите логотипы в `assets/logos` и укажите относительные пути в `source.txt`.

## Проверка перед публикацией

1. Запустите локальный сервер и откройте сайт.
2. Проверьте обе вкладки, поиск, фильтры, переключение темы и Liquid Glass.
3. Откройте консоль браузера: ошибок и нарушений CSP быть не должно.
4. Убедитесь, что в репозиторий попали `.nojekyll`, `assets/theme-init.js` и `.github/workflows/pages.yml`.
5. В **Settings → Pages** выберите **Source → GitHub Actions**.

## Что стоит знать

- Логотипы грузятся с внешних CDN (Simple Icons, raw.githubusercontent.com, сайты проектов). Если CDN недоступен, карточка остаётся с буквенной плашкой — сайт от этого не ломается.
- Сайт ничего не скачивает и не раздаёт: только ссылки на официальные источники.
- Поиск ищет по названию, описанию, категории и платформам. `/` ставит курсор в поиск, `Esc` очищает его.
- Категории прокручиваются стрелками и колесом мыши.
- Тема, акцентный цвет и Liquid Glass сохраняются только в браузере посетителя.
